# v1.0.21 MCP 입력과 출시일 처리

MCP가 받는 카드사명은 `bc`, `hana`, `hyundai`, `kb`, `lotte`, `samsung`,
`shinhan`, `woori`의 8개 코드로 정규화한다. 등록된 한글·영문 별칭을 허용하고,
알 수 없는 이름은 저장소를 조회하기 전에 명시적인 도구 오류로 반환한다.

## 최근 출시상품 계약

`list_recent_products(months=1, issuer="KB국민카드")`는 공식 출시일이 조회 기간에
포함되는 현재 상품만 반환한다. `months`는 1~120의 정수이며, 기간은 오늘에서
해당 개월 수를 뺀 날짜부터 오늘까지 양 끝을 포함한다. 해당 월에 같은 일자가
없으면 말일로 맞춘다. 예를 들어 2026-09-09 기준 1개월은 2026-08-09~2026-09-09다.

- `launch_date`: 공시 원문에 명시된 출시일. 출시일 누락·잘못된 날짜·상충하는
  여러 출시일은 `null`로 유지한다. 중복된 동일 날짜는 허용한다.
- `effective_date`: 문서나 계약 개정의 시행일. 최근 출시 포함 여부나 출시일
  정렬의 대체값으로 사용하지 않는다.
- `period_start`, `period_end`: 실제 사용한 출시일 필터 범위.
- `unknown_launch_date_count`: 조회한 카드사 범위의 현재 상품 중 출시일을 확정하지
  못한 수. 최근 출시 건수가 아니며 해당 상품들의 출시 시점은 알 수 없다.

미래 출시일과 과거 출시 상품의 최근 개정은 최근 출시 목록에서 제외한다.
`find_products`, `get_product_summary`와 최근상품 조회는 같은 출시일 해석을 사용한다.
이 도구는 기존 v1.0.15에서 도입됐으며, v1.0.21에서 최근 출시 기준과 입력 검증을 강화한다.

기존 클라이언트는 `items`, `total_count`, `generation_id`를 계속 사용할 수 있다.
`list_recent_products`를 개정 상품 검색에도 사용하던 클라이언트는 변경된 출시 전용
의미를 따라야 한다. 상품의 개정 이력은 `list_product_revisions`로 조회한다.

## LibreChat와 검증

상품안내장 Agent는 반환된 기간과 `launch_date`로 최근 출시를 판단한다.
출시일이 없는 개별 상품은 `[확인 필요: 출시일 미확인]`으로 표시하고,
미확인 건수를 최근 출시 건수로 더하거나 개정일을 출시일로 추정하지 않는다.

검증은 날짜 형식·기간 경계·미래일·개정일 혼입·미확인·상충 날짜 회귀 테스트와
MCP 실제 도구 호출, LibreChat 관리 Agent의 실제 대화로 수행한다.
실제 대화에서는 도구 입력/결과와 최종 답변의 출시일 일치, `null` 및 확인 필요 표시를
확인하고 인증정보를 제외한 검증 자료를 보존한다.

배포 대상은 MCP와 관련 Agent 설정이다. 실행 중인 OCR worker, worker 예약,
worker 데이터·인증 volume 및 WebDAV 게시 상태를 변경하지 않는다.
실행 중인 worker가 있는 동안의 예약 중복 실행 실패는 현재 운영상 정상으로 취급한다.
