# FIX_33 변경01 — 같은날 자동 순회3회 허용 및 KST13시 예약

2026-10-22 사용자 정책 변경. 본 문서는 FIX_33의 "terminal result 재사용 정책을 변경하지 않는다"와 충돌하는 부분보다 우선한다. Executor는 CLI 이중 출력 수정과 아래 정책을 함께 구현·검증·운영 반영한다.

- KST날짜/channel별 카드사1개 고정은 유지하되 완료된 자동 순회 이후 같은 날 새 실행을 최대3회 허용한다.4번째는 명시적인 blocked/nonzero이며 원본/배치 처리와 queue 전진을 하지 않는다. 성공/no_change/실패 모두 실배치 시도1회로 센다.
- 같은 날2·3회는 같은 카드사의 새 run으로 실행하고 기존 run/결과는 별도 시도 이력으로 보존한다. 다음 날짜에만 다음사로 전진한다. 중단된 미완료 run의 안전한 재개는 같은 시도로 취급한다. 명시 수동 issuer 선택의 기존 비순회 계약은 유지한다.
- 기존 day row는 기존 실제 배치1회로 호환 이행한다. 오늘10시 우리 실배치=1회,12시 저장 결과 반환은 새 실배치가 아니므로 추가 차감하지 않는다. 따라서 오늘13시는 우리2회차다. DB를 SQL로 수작업 초기화하지 않고 애플리케이션 schema/호환 이행으로 처리한다.
- 재부팅/이미지 교체 후에도 회수·시도 이력·다음 큐를 유지한다. same-day 신규 실행과 unfinished/sealed reconciliation을 구분하고 이전 정상 게시를 롤백하지 않는다.
- timer는 매일13:00 Asia/Seoul/Persistent=false로 변경한다. 오늘부터 next elapse가13시가 되도록 실제 설치·활성화하며 sudo 인증은 사용자 복붙 명령으로 수행한다.13시 전에 수동 run으로 시도를 소비하지 않는다.
- 정상/실패/중단의3회·4회차 차단,DB reopen/legacy migration/다음날/미선택·수동비소비,CLI단일JSON/exit,취소·봉인 재개 회귀와 전체Worker/Core·정적 검사를 확인한다. image/실제volume/lock/복구점·용량을 보존하고 FIX_33_REPORT에 정확한 구현·배포·미실행 범위를 적는다.
