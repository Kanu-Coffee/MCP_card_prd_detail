# 019 계획 변경 01 — 22건 전체를 최신 기준으로 갱신

2026-10-19 사용자 정책 변경 반영. **본 문서가 PLAN.md의 충돌하는 요구보다 우선한다.** 기존 PLAN/ANALYSIS는 조사·결정 이력으로 보존한다. 현재 작업은 Planner의 계획 변경이며 구현·삭제·배포·origin 재호출을 실행하지 않았다.

## 사용자 결정

미해결 이력 22건 전체가 대상이다. 이 프로젝트는 최신 상품의 정확성과 배치 정상 처리를 우선한다. 현재 시점에 존재하지 않는 상품의 과거 자료는 없어져도 된다. 소수의 레거시 이력을 복원·계승하려고 코드를 과도하게 복잡하게 만들지 않는다.

따라서 기존 PLAN의 “22건 원래 identity와 reason을 반드시 새 seal에 계속 계승” 및 메타데이터 없는 과거 source를 복원하는 범용 resolver 설계는 철회한다. 대신 기존 검증된 미해결 ledger를 대상으로 현재 목록과 최신 유효 PDF를 기준으로 갱신하고, 복구 불가능한 과거 이력은 활성 게시/개정 확장 대상에서 제외한다. 이는 사용자 승인된 보존 요구의 제한적 변경이며 전체 역사 기능 삭제나 모든 PDF 캐시 초기화 요청이 아니다.

## 추가 확인한 대상 규모

운영 baseline seal을 네트워크 없는 컨테이너에서 읽고 SQLite mode=ro로 source의 issuer를 조회했다.

- 총 22개 source_id/pdf_sha256 identity. 상품 22개나 파일 22개라고 단정하지 않는다.
- 사유: document_identity_collision 17개, source_metadata_unresolved 4개, pdf_cache_object_unavailable 1개.
- PDF cache source 행 기준: 현대 17개, 하나 3개, 우리 1개, BC 1개.
- 이 건수/카드사는 조사 결과일 뿐 처리 분기·하드코딩 조건으로 사용하지 않는다.

## 실행 설계 — 작은 범위의 갱신을 우선

1. **범위 고정과 복구점**: 실제 current serving에 결합된 검증된 baseline seal의 unresolved ledger에서 대상을 산출한다. source_id/pdf_sha256/사유, 연결된 source/revision/document, 공유 CAS 참조 및 현재 게시 여부를 inventory로 남긴다. 필요한 SQLite/serving 복구점을 확보한다. 운영 전체 8사 5536문서나 PDF 캐시 전체를 리셋하지 않는다.
2. **현재 목록 기준 갱신**: 기존 adapter·캐시·재처리 기능을 우선 재사용한다. 선택 카드사의 정상적으로 완료된 현재 목록에서 대상 product/document lineage의 최신 유효 PDF를 확인하고, 캐시 검증/필요한 핀포인트 다운로드 및 OCR을 수행한다. 한 번의 개선 작업 때문에 전체 PDF를 다시 다운로드하지 않는다. 현재 상품에 정상 최신 자료가 있으면 그것이 우선한다.
3. **과거 오류 이력 정리**: 위 22개와 이후 동일하게 발생하는 복구 불가 과거 identity는 현재 자료의 정상 처리 및 비선택 보존을 차단하지 않게 한다. 과거 오류 entry를 새 ledger에서 지우는 것만으로 끝내지 않는다. 다음 배치의 cache history 확장에서 같은 identity가 재유입되지 않도록 기존 상태/개정 계획 경계에서 가장 작은 정리 또는 제외 정책을 구현한다. 별도 복잡한 메타데이터 복원 계층보다 단순하고 검증 가능한 방법을 택하고 REPORT에 근거를 남긴다.
4. **현재 상품 우선 보호**: 과거 collision identity의 document_id가 현재 정상 문서와 겹치면 과거 쪽만 제외하고 현재 문서는 유지한다. source 전체를 지워 활성 revision까지 제거하거나 FK/previous_revision_id/supersession을 깨뜨려서는 안 된다. PDF 객체가 공유되면 원본 바이트를 즉시 삭제하지 않고 기존 GC에 맡긴다. 정리를 위한 별도 대규모 GC/디스크 확보 작업은 하지 않는다.
5. **현재 미존재 상품**: 해당 카드사의 최신 목록 수집이 정상·완전하게 완료됐다는 증거가 있을 때 대상의 옛 자료는 활성 게시에서 제외 가능하다. 목록 호출 실패·부분 수집·not_scheduled를 “현재 없다”로 해석하지 않는다. 비선택 카드사의 현재 상품 존재 여부를 우리 실행에서 추측해 삭제하지 않는다. 비선택 7사의 serving 문서는 기존 선택 실행 계약대로 유지하고, 필요하면 해당 카드사의 차례에 최신 자료로 갱신/제외한다. 비선택의 과거 미해결 ledger는 계승하지 않아도 되지만 그 변경을 remediation 결과에 명시한다.
6. **재처리 실패**: 현재 존재하는 상품인데 다운로드/DRM/ZIP/OCR 오류가 나면 기존 마지막 정상본 보호와 degraded/오류 기록 정책을 유지한다. 장애를 상품 소멸로 오인해 지우거나 unresolved=0만으로 성공 처리하지 않는다. 현재 바이트/현재 identity의 무결성 오류 검증은 약화시키지 않는다.

Executor는 관련 코드와 기존 도구를 확인해 최소 변경안을 선택한다. 운영 DB를 ad-hoc SQL로 수작업 변경하거나 기존 immutable seal/게시 DB를 덮어쓰지 않는다. 일회성 정리 도구가 가장 단순하면 기존 운영 도구 체계 안에 dry-run/대상 목록/적용 결과/재실행 안전성을 갖추고, 장기 분기나 상품 예외 목록을 만들지 않는다. 외부 현황이 이후 바뀌면 정상 최신 자료가 다시 채택될 수 있어야 한다.

## 인수·검증 변경

기존 PLAN의 비선택 호출 금지·현재 serving 보호·lock/fence·프로필/해시·재개·90일 감사·freshness·백업·ZIP 정책과 필요한 회귀 검증은 유지하되, 과거 22건의 무조건 계승 검사는 아래로 대체한다.

- baseline 미해결 ledger로부터 대상 22개를 산출하고 처리 전/후 disposition(최신본 갱신, 과거 제외, 현재 오류 잔존 등)을 모두 설명한다. fixture는 실제 product/source ID를 하드코딩하지 않고 세 사유를 재현한다.
- 현재 문서와 과거 collision이 겹쳐도 현재 문서와 공유 CAS를 유지한다. source metadata 없는 과거 이력과 과거 cache object 부재가 선택 실행을 막지 않는다.
- 같은 배치 재실행·다음 카드사 실행·전체 배치·재개에서 제외된 과거 identity 때문에 다시 막히거나 새 ledger에 그대로 재유입되지 않는다. 새 current PDF의 정상 변경은 탐지한다.
- 최신 목록의 정상 미존재와 목록 실패/부분 수집/not_scheduled를 구분한다. 전자는 대상 레거시 자료 제외를 허용하고 후자는 현재 자료를 보존하며 정확한 상태를 남긴다.
- 비선택 문서/OCR/구조/embedding은 우리 실행 전후 유지된다. 별도 허용된 과거 ledger 정리를 문서 손실과 구분해 보고한다. 하나/현대/BC가 자신의 차례에 최신 기준으로 갱신되는지 검증한다.
- 기존 PLAN에 명시한 관련/전체 Worker 테스트·ruff, 사용자 수동 우리 재검증 → 나머지 7사 → timer 조정 순서를 유지한다. 백업 완료와 degraded 여부를 별도로 확인한다.

Executor의 REPORT는 이 변경 문서를 읽었음을 밝히고, 구현 복잡도·정리 범위·실제 잔여 unresolved·현재 자료 영향·미검증 운영 항목을 기록한다. 22건을 강제로 0으로 만드는 것이 목표가 아니라 현재 자료의 정상 처리를 막는 불필요한 과거 의존성을 제거하는 것이 목표다.
